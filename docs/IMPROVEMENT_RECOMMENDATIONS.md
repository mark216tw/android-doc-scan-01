# 介面與功能優化建議

本文件依 2026 年 9 月 17 日的程式實作整理，涵蓋使用流程、可靠性、無障礙、在地化與測試。對應的可執行工作及唯一編號請參閱[優化待辦事項](IMPROVEMENT_TODO.md)。

## 評估摘要

目前版本已完成掃描或相簿匯入、頁面排序與刪除、JPEG/PDF 匯出、Room 草稿保存及主題設定，適合用於單次、短文件掃描。優先改善方向應是讓既有資料可再次存取、避免誤刪與輸出錯誤，以及讓長文件操作有明確進度與限制。

| 優先級 | 目標 | 主要價值 |
| --- | --- | --- |
| P0 | 文件庫、刪除復原、整份文件頁數限制、作業狀態 | 避免資料遺失、隱藏草稿與競態操作 |
| P0 | 多張 JPEG 正確開啟及分享、匯入與匯出失敗清理 | 確保介面承諾與實際結果一致 |
| P1 | 重新命名、完整預覽與編修、拖曳排序、匯出選項 | 提升主要掃描工作流效率與可控性 |
| P1 | 錯誤復原、裝置需求說明、自適應版面 | 降低首次使用失敗與不同裝置上的操作障礙 |
| P2 | 無障礙、字串資源、App 內隱私與授權入口 | 改善可及性、翻譯能力與資訊透明度 |
| P2 | 測試邊界、資料庫遷移與壓力測試 | 降低後續功能擴充造成的回歸風險 |

## P0：先處理資料與流程可靠性

### 1. 新增文件庫與草稿生命週期

Room 已保存多份文件，但 App 啟動時只開啟最近更新的一份；建立新文件後，舊草稿仍占用空間卻無法在介面重新開啟。建議新增文件庫首頁，提供建立、開啟、重新命名、刪除及顯示頁數與更新時間，並清理未加入頁面的空白草稿。

預期效果：使用者能管理多份工作，不會因點選「新文件」而失去舊草稿的入口。

依據：`ScanDao.kt` 只有最近文件查詢，`ScanViewModel.kt` 只維護單一 `activeDocumentId`。

### 2. 刪除頁面需確認並支援復原

目前按下「刪除」會立即刪除資料庫記錄及私有圖片，沒有確認或復原。建議先從畫面移除並顯示 Snackbar「復原」，延遲實際刪檔；若採確認對話框，至少應顯示頁碼與縮圖。批次刪除可在文件庫完成後再加入。

預期效果：降低觸控誤按造成的永久資料遺失。

### 3. 對整份文件執行 50 頁限制

已完成：啟動掃描前會依現有頁數設定 ML Kit 的剩餘頁數上限，匯入時由資料層再次驗證，主畫面也會顯示「目前頁數 / 50」及剩餘容量。

預期效果：讓 README 的功能說明與實際行為一致，避免超大型匯出造成記憶體或時間問題。

### 4. 統一掃描、匯入與匯出的作業狀態

目前 `isWorking` 主要包住匯入及匯出，但取得掃描 Intent 的期間沒有鎖定，匯出時頁面排序、刪除及設定仍可操作。建議建立單一作業狀態，例如準備掃描、匯入第 N 頁、輸出第 N 頁，停用所有會改變文件內容的衝突操作，並顯示可理解的進度。

預期效果：避免重複啟動、匯出途中刪檔及使用者誤以為 App 無回應。

### 5. 修正多張 JPEG 的開啟與分享語意

JPEG 匯出會儲存全部頁面，但只回傳最後一張圖片 URI，因此「開啟」與「分享」只處理最後一頁。建議讓匯出結果保存全部 URI，分享時使用 `ACTION_SEND_MULTIPLE`；開啟操作則改為開啟匯出位置，或明確標示只開啟最後一張。

預期效果：匯出完成後的操作符合「已儲存 N 張圖片」訊息。

### 6. 確保檔案與資料庫一致

多頁匯入若中途失敗，先前已複製的檔案不會寫入資料庫也不會清除；多張 JPEG 匯出若後段失敗，也可能留下已完成檔案。建議加入整批回滾或明確的部分成功結果，並在啟動或維護流程清理孤兒檔案與過期空白草稿。

預期效果：避免儲存空間持續累積不可見檔案，也能正確告知部分成功。

## P1：改善核心使用體驗

### 7. 提供可操作的錯誤與首次使用說明

目前直接顯示 `localizedMessage`，可能包含技術訊息；資料庫初始化失敗時也可能一直停在載入畫面。建議定義穩定的使用者訊息與「重試」動作，區分取消掃描、Google Play 服務不可用、元件下載中、來源圖片無法讀取及儲存空間不足。首次使用或說明頁應交代 Play 服務、網路下載、記憶體及相機需求。

### 8. 支援文件重新命名與輸出目的地

文件名稱目前以分鐘產生且不可編輯，輸出路徑固定。建議允許在文件庫或匯出前重新命名，保留一鍵匯出預設位置，同時透過 Storage Access Framework 提供自選檔名與位置。

### 9. 新增完整頁面預覽與基本修正

目前只有固定大小縮圖，無法在匯出前檢查細節。建議點選縮圖進入全螢幕預覽，第一階段提供縮放、旋轉與替換；後續再評估重新裁切、濾鏡與亮度調整。編輯結果應保留原圖或提供復原，避免反覆壓縮。

### 10. 以拖曳改善長文件排序

逐次按「向左／向右」不適合長文件。建議增加拖曳把手、自動捲動及移動後頁碼回饋，同時保留「移至前一頁／後一頁」無障礙動作，並使用前後而非左右語意以支援 RTL 介面。

### 11. 增加 PDF 與圖片輸出選項

PDF 目前固定為 A4 直向、固定邊界及點陣圖片。建議先提供 A4／Letter／依原圖、直橫向、邊界及壓縮品質；進階階段再評估 OCR 與可搜尋 PDF。所有設定應有合理預設值，不增加快速匯出的步驟。

### 12. 改善小螢幕、橫向與大字體版面

主畫面使用固定高度區塊且整頁不可垂直捲動，在小螢幕、分割畫面、橫向或大字體時可能裁切。建議讓主要內容可捲動，匯出操作在空間足夠時固定於底部；平板可採文件清單與預覽雙欄。至少測試 200% 字體、橫向及常見分割畫面寬度。

### 13. 簡化頂端操作與導覽

頂端列同時包含長文件名稱、「新文件」、設定及將 App 移至背景，空間容易不足。「移至背景」與系統 Home 操作重複，建議移除；建立文件庫後採標準首頁、文件編輯、設定三層導覽，低頻動作放入 overflow menu。

### 14. 保存清楚的匯出結果與紀錄

目前只保留單一記憶體內 URI，文件頁面 Flow 再次發送就會清除。建議顯示檔名、格式、頁數、目的地及時間，並保存最近匯出紀錄；提供開啟檔案、分享及在支援的裝置上查看位置。

## P2：可及性、在地化與產品資訊

### 15. 完善 TalkBack 與鍵盤操作

每張頁面目前都只有相同的「向左／刪除／向右」文字。建議加入集合位置、頁碼上下文、選取狀態與完成公告，例如「將第 3 頁移至第 2 頁」，並檢查焦點順序、觸控目標及外接鍵盤操作。

### 16. 改善設定頁語意與色彩選擇器

色相滑桿缺少可見標籤與可理解數值，主題選項也未明確暴露選取狀態。建議增加「自訂色相」標籤、色彩名稱或角度描述、選取語意、區段標題語意及對比預覽，並驗證自訂色在淺色與深色模式的可讀性。

### 17. 將介面文字移至字串資源

目前大部分中文字串直接寫在 Compose 與資料層。建議移入 `strings.xml`，頁數使用 plurals 或格式化資源，錯誤訊息與內容描述也統一管理。這會讓術語一致、UI 測試穩定，並為後續語系預留空間。

### 18. 在設定頁提供隱私、儲存與授權資訊

設定頁目前只顯示版本及 Build。建議加入隱私說明、開放原始碼授權、草稿與匯出位置、資料刪除方式，以及 Google Play 服務處理掃描功能的說明。

## 工程品質與驗證

### 19. 建立可測試的依賴邊界

`ScanViewModel` 直接建立 Room、Repository 與 Exporter，使單元測試難以替換失敗情境。建議注入介面或工廠，將一次性事件與持久 UI 狀態分離，優先覆蓋頁數限制、刪除復原、匯入回滾及多 URI 分享。

### 20. 建立資料庫遷移與壓力測試基線

目前資料庫版本為 1 且未輸出 schema。加入文件名稱、OCR 或匯出紀錄前，應啟用 schema export、建立 migration test，並針對 50 頁、高解析圖片、低儲存空間、程序重建及旋轉畫面執行測試。

## 建議交付順序

1. 先完成 `SDS-001` 至 `SDS-006`，消除資料不可見、誤刪與輸出不一致。
2. 接著完成錯誤處理、重新命名、完整預覽與自適應版面，形成可靠的主要流程。
3. 再加入進階輸出、匯出紀錄、無障礙與在地化。
4. 每一階段同步補測試與資料庫遷移，不將品質工作留到功能全部完成後。
